# ASIA BASA

Белая премиальная витрина азиатских продуктов + закрытая админка `/admin`.

## Стек и запуск
Проект на managed-стеке Runable: **Bun + React 19 + Vite + Tailwind 4 + Hono/oRPC + Drizzle/Turso**. Для установки и запуска достаточно **Node.js 22.12+ и npm**. Глобальные `bun`/`bunx` не нужны: `npm run dev` запускает Vite напрямую, а Bun 1.3.14 для БД и production-сервера устанавливается локально как npm-зависимость. Это npm-совместимый запуск, не замена production-runtime на Node.js.

```sh
npm ci
```

Скопируйте `.env.template` в `.env` **в корне проекта**:

```bat
REM Windows CMD
copy .env.template .env
```

На macOS/Linux: `cp .env.template .env`. Заполните в `.env` `BETTER_AUTH_SECRET` (32+ случайных символа), `ADMIN_EMAIL` и `ADMIN_PASSWORD` (12+ символов). Для локального запуска оставьте `WEBSITE_URL=http://localhost:4200` и `DATABASE_URL=file:./local.db`. База будет создана в `packages/web/local.db`; команды БД, dev и production используют один рабочий каталог.

```sh
npm run db:push
npm run db:seed
npm run dev
```

**Не добавляйте `--ignore-scripts`**: локальный Bun и Electron используют install-скрипты для установки бинарников. `.npmrc` уже включает `legacy-peer-deps` для исходного multi-platform шаблона. Если npm ранее был запущен с `--ignore-scripts`, выполните обычный `npm ci` заново. При обновлении скачайте свежую версию проекта или сделайте `git pull`, сохранив свой `.env`.

Web: http://localhost:4200 — порт определяется `__ports.cjs`. Доступен и стандартный managed-запуск `bun install && bun run dev`.

```sh
npm run build:web    # Проверка TypeScript и сборка магазина
npm run build        # Сборка всех пакетов шаблона
npm run typecheck
npm run start        # Production-сервер после сборки (PM2)
npm run stop
npm run kill:port    # Освободить порт магазина; Windows / Linux / macOS
```

Windows-команды запуска не содержат `$(...)`, `lsof`, `cd ... && bunx` или перенаправления в `/dev/null`. Нативная проверка Windows в Linux sandbox недоступна; используйте Node.js x64 и обычный CMD/PowerShell, без WSL.

Проверка этой версии: чистый `npm ci`, `db:push`, `db:seed`, `dev`, `build:web`, `start` и `stop` в каталоге с пробелами, с PATH без глобальных Bun/bunx (Linux, Node.js 26.8.2, npm 11.19.1). Через браузер проверены каталог, вход/перезагрузка/выход администратора и мобильная вёрстка — в dev и production.

## Переменные окружения
Все секреты только в корневом `.env` (не коммитится). Для клона используйте собственную Turso/SQLite базу; доступа к рабочей базе в репозитории нет.
- `DATABASE_URL` (например `file:./local.db` или URL Turso)
- `DATABASE_AUTH_TOKEN` (для Turso; для локального SQLite пустой)
- `BETTER_AUTH_SECRET` — случайный секрет не короче 32 символов
- `WEBSITE_URL` — полный URL приложения, локально `http://localhost:4200`
- `AUTH_TRUSTED_ORIGINS` — дополнительные явно разрешённые origins через запятую, если доверенный preview-прокси переписывает заголовок Origin; по умолчанию пусто. Не используйте wildcard или произвольный адрес посетителя.
- `ADMIN_EMAIL`, `ADMIN_PASSWORD` — закрытый администратор, пароль минимум 12 символов
- `APPLICATION_ID` и соответствующие `VITE_*` — managed-параметры платформы (в Runable настроены автоматически)

`db:seed` идемпотентен: не перезаписывает существующие товары, настройки и пароль администратора. Для нового администратора задайте email и пароль до первого запуска. Публичная регистрация отключена. Смена `ADMIN_EMAIL` меняет серверный allowlist; для создания новой записи выполните seed. Пароль существующего пользователя seed не меняет.

## Админка
`/admin` → вход по настроенному email и паролю. Все операции изменения защищены серверной проверкой Better Auth сессии + allowlist email. Токен сессии хранится в sessionStorage текущей вкладки.

- Каталог: создание, изменение, удаление и скрытие товаров; цена, старая цена, острота, бренд, категория, описания, порядок, бейдж, рекомендованность, себестоимость.
- Наборы: редактирование состава из существующих товаров и количества; цена набора устанавливается вручную.
- Фото: загрузка JPG/PNG/WebP до 2 МБ; сервер проверяет декодирование, нормализует в WebP до 1200 px. Хранятся в базе вместе с товаром. Допускается внешняя HTTPS-ссылка.
- Настройки: бренд, заголовок, текст, ИНН/ОГРН, юрлицо, телефон, email, адрес, часы, Telegram/VK/Авито, порог бесплатной доставки и её стоимость, доставка, оплата, возврат, политика конфиденциальности, оферта.
- Нельзя удалить товар, входящий в состав набора: сначала исключить из состава или скрыть.

Изменения доступны всем посетителям; каталог обновляется при возврате на вкладку или перезагрузке. Контакты и реквизиты намеренно пустые, а правовые тексты требуют заполнения реальными сведениями.

## Каталог из Excel
52 отдельных товара и 13 наборов; состав привязан по исходным ID. Розничные цены взяты из файла как предварительные ориентиры. В рабочей базе сохранена себестоимость из Excel, но **в публичном исходном seed закупочные цены и исследовательские оценки удалены**. В свежем клоне себестоимость нулевая до ввода администратором. Исходная таблица не опубликована.

Для «Чайного Шёлка» не заявляется скидка: цена включает упаковку и превышает сумму отдельных товаров. Старые цены из исходной таблицы не выдумываются.

## Границы текущей версии
- Изображения по умолчанию — подписанные иллюстрации-заглушки, не реальные фото.
- Корзина рабочая и сохраняется локально. Добавлен приём заявок без оплаты с сохранением в БД и уведомлением администратора через Telegram. По умолчанию приём выключен. Эквайринг, кассовые чеки, полноценная CRM и рассылки не подключены. Подробнее — `TELEGRAM-ORDERS.md`.
- Сервер сохраняет товары и настройки в базе; базу нужно резервировать отдельно. Репозиторий не является резервной копией рабочей БД.
- Three.js-футер — деликатные металлические/нефритовые формы с параллаксом, fallback на светлый фон при отсутствии WebGL.

## Безопасность зависимостей
В v2 обновлены Better Auth, JOSE и oxfmt. Аудит установленного монорепозитория: 63 предупреждения (23 moderate, 39 high, 1 critical), преимущественно в не обновлённых mobile/desktop/tooling и PM2. Аудит production-зависимостей web-workspace с `--omit=dev`: 0 известных предупреждений на дату проверки, что не является сертификатом безопасности приложения. Для production рекомендована отдельная установка только web-runtime и системный сервис вместо включения всего шаблона/PM2. Инструкции и границы проверки — `TELEGRAM-ORDERS.md`, `TEST-RESULTS-V2.md`.
